# Settings

Four top-level entries from the journal overflow menu:

- **Account** (`AccountSettingsScreen`): server URL, username (read-only), Log out (tonal error button).
- **App settings** (`AppSettingsScreen`):
  - Show private tracks (switch).
  - Editable days (segmented: Today / +1 day / 1 week / All).
  - Journal layout (segmented: Days down / Tracks down).
  - Grid density (segmented: Low / Medium / High).
  - Theme (segmented: System / Light / Dark).
- **Tracks settings** (`TracksSettingsScreen`): every track (private included) in journal order. Row: drag handle (48dp target) · 40dp `TrackBadge` · name with a grey "Yes/No" / "Counter" (+ " · Private") line · chevron. "?" opens `TracksHelpSheet` (shared with the track screen). A FAB ("Add track") opens `NewTrackSheet` (name capped at 255 code points via `capTrackName`, type Yes/No | Counter with Yes/No default, Private switch); on success the sheet closes and the list scrolls to the new track, on failure it stays open with what was typed and "Add track" retries.
  - **Drag to reorder** uses the Reorderable library (`rememberReorderableLazyListState`, `ReorderableItem`, `Modifier.draggableHandle(onDragStopped = commitOrder)`). `TracksSettingsViewModel` holds a `pendingOrder` (local ids) applied over Room's rows (`applyOrder`), and each drop sends the full order. It is cleared only when the **last** in-flight reorder returns *and* Room's rows have caught up (bounded wait), so the list never jumps back between quick drops or for a frame after the save; a failure clears it at once (snap back + toast). Screen-reader users get "Move up" / "Move down" custom actions on each row instead; the handle is its own semantics boundary hidden from accessibility, so its offline "disabled" can't merge into the row (which still opens the track).
- **Archived tracks in Tracks settings** (only with the flag; `TracksSettingsViewModel` empties `archived` without it): after the active rows, a "Archived (n)" toggle row (`testTag("archived-header")`, hidden when nothing is archived) and, while open, the archived rows (`"archived-<localId>"`): alphabetical by a PRIMARY `Collator` (`sortArchived`), greyed, no handle or chevron, a muted `TrackBadge`, and "Yes/No · Archived 14 Aug 2026" (`getBestDateTimePattern(locale, "dMMMy")`). The open state is `rememberSaveable` in the screen: collapsed on every visit, kept across opening a track or rotating, opened after every archive. A tap (online) opens `ArchivedTrackDialog` (Restore · Cancel · Delete via `SplitDialogButtons`, a weighted `FlowRow` that wraps the start button onto its own line at large font sizes); Delete opens the step 4 confirm **without** "Archive instead". Restore and delete run in the list's ViewModel and wait for Room before their events. **The reorder callback casts keys with `as? Long`**: the archived rows and header use String keys and aren't `ReorderableItem`s; `move()` also ignores non-active ids. Every track archived: the empty text is the list's first item with the Archived row under it.
- **Back to the list after an archive** uses a navigation result: `TrackDetailScreen.onArchived(serverId)` writes `justArchivedServerId` into the previous entry's `SavedStateHandle` and pops (only while `RESUMED`, as for delete); the list opens its Archived row and scrolls to the track, then clears the key. `TrackDetailViewModel` observes `observeAllTracks()` and keeps the last active track while its own archive runs (so no flash of "Track not found."); a track archived elsewhere reads "Track not found.".
- **Track screen** (`TrackDetailScreen`): title = name (ellipsized, `weight(fill = false)`) with a rename pencil right after it (`TrackTitle`), "?" at the end. 56dp preview badge + type ("Yes/No" / "Counter" only). Private switch (saves straight away; shows the new position, disabled, until the server answers; reverts on failure). Custom colour row (label and help text say "colour": UI copy uses British spelling). Icon row (`TrackIconRow`), one scrolling `LazyRow`: letters ("no icon") · "⋯" (opens `EmojiPickerSheet`; second so it's always in view, since the scroll alone proved hard to discover — it was first pinned at the end edge) · a custom emoji if set · ten fixed habit emojis (`IconChoices.HABIT_EMOJIS`, matched ignoring U+FE0F via `sameEmoji`, so an icon saved without the variation selector still selects its circle); the custom circle stays when the user then taps a habit, so the row never shifts under the finger. "Archive track" (full-width `FilledTonalButton`, 12dp above Delete, only with the flag) → `ArchiveTrackDialog` → back to the list. "Delete track" (full-width `errorContainer` button, styled like Account's "Log out") → confirm (with "To keep its history, archive it instead." and an "Archive instead" button when the flag is set) → back to the list. Rename and delete are `AlertDialog`s (`TrackDialogs.kt`); a failed rename stays open, a failed delete closes. **While its own delete runs and until the back navigation, `TrackDetailViewModel` keeps the last track and prefs in state**: the re-read removes the row (and sweeps its prefs) before the screen leaves, which would otherwise flash "Track not found." The `Deleted` event only pops if the screen is still `RESUMED`, so a Back pressed mid-delete can't pop the list too. "Reset to defaults" is gone (Default colour and the letters circle do its job), as is `TrackPrefsRepository.reset`.
  - **Colour and icon rows**: `Modifier.edgeFade` (32dp, `DstIn` over an offscreen layer, only on an edge with more to scroll, mirrored in RTL) and `OpeningScroll`, which once per visit (saveable flag) scrolls the selection clear of the end fade (`openingScrollPx`, pure).
  - **Emoji picker trap**: the activity theme is `Theme.Material.Light` in every mode and dark mode exists only in Compose, so a hosted View always draws light. `EmojiPickerSheet` wraps the context in `Theme_Material` / `Theme_Material_Light` from the Compose colour scheme's luminance and keys the `AndroidView` on it. **Touch race with the sheet (do not regress):** Compose gives a hosted View each move event first but lets an ancestor take it unless the View has called `requestDisallowInterceptTouchEvent`, and RecyclerView only calls that once it is already scrolling — one event after the sheet's `anchoredDraggable` has crossed the same touch slop. So drags on the picker moved or dismissed the sheet and the list barely scrolled. The picker sits in `TouchClaimingHost`, a `FrameLayout` that requests disallow-intercept on `ACTION_DOWN`; the sheet still drags (and dismisses) by its handle and title row. Nested scrolling isn't bridged (the holder only bridges when the *root* view has `isNestedScrollingEnabled`, and a slow release then wouldn't settle the sheet), and `rememberNestedScrollInteropConnection` is the wrong tool here — it is for Compose inside a View parent. Coverage: `EmojiPickerSheetTest`, which swipes with Espresso's real `MotionEvent`s; Compose's `performTouchInput` doesn't reproduce the race. Its recently-used list is the library's own and survives sign-out.
  - **Offline**: `NetworkMonitor.isOnline` via each ViewModel's `online` StateFlow. The FAB, handles, pencil, Private and "Delete track" grey out with no banner; `OfflineGuard` draws the control disabled and lays a clickable overlay on top (a disabled control ignores taps) that shows "You're offline. Changes to tracks need a connection." The FAB has no `enabled`, so `AddTrackFab` draws M3's disabled colours itself. A sheet/dialog left open when the connection drops shows the same toast instead of saving. All feedback is `Toast`s on errors only, sent as one-shot events through a `Channel`.
  - Colour/icon edits write through immediately; the server controls are also disabled if the track has no `serverId` (can't happen — tracks only enter Room through a pull — but the guards cost nothing).
- **About** (`AboutScreen`, package `ui.about`): app name, version (resolved at runtime via `PackageManager.getPackageInfo`), one-line description, copyright, GPL-3.0 link to `LICENCE` on GitHub, and two outlined buttons, "Visit tickbuddy.app" above "View source on GitHub" (`Intent.ACTION_VIEW`).
