# Tests

The full suite is 335 JVM unit tests + 273 instrumentation tests (608 total), including the widget tests listed in `.claude/rules/widgets.md` and the track-management tests (JVM: `TrackNamesTest`, `OcsErrorTest`, `TrackEditorTest`, `TrackOrderTest`, `IconChoicesTest`, `ScrollableRowFadeTest`, and the two settings ViewModel tests; instrumentation: `TrackChangesTest` on `SyncTestRig`, asserting requests, Room and the lock, `TrackSettingsUiTest` on the content composables, and `EmojiPickerSheetTest`) and the archive tests (JVM: `ServerFeaturesTest`, `ArchivedTracksTest`, `TracksHelpSheetTest`, `TrackDtoTest`, plus cases in the editor, ViewModel and widget tests; instrumentation: `MigrationTest`, `TrackDaoTest`, and cases in `SyncManagerPullTest`, `TrackChangesTest`, `PushWorkerTest`, `SyncCoordinatorTest`, `TrackSettingsUiTest`, `SingleTrackWidgetTest`). Dragging itself is only checked by hand (the library has its own tests). Unknown track types: JVM `TrackTypeTest`, `TickDtoTest`, plus cases in `WidgetModelsTest`, `WidgetTickHandlerTest`, `ArchivedTracksTest`, `TrackEditorTest`; instrumentation cases in `SyncManagerPullTest`, `PushWorkerTest`, `TickCellInteractionTest`, `TrackSettingsUiTest`, the three widget tests and `WidgetRemoteViewsTest`. Rejected writes (423, and 404 / 400 with a `reason`): JVM `PushFailureTest`, plus cases in `OcsErrorTest`, `OcsHeadersInterceptorTest` and `TrackEditorTest`; instrumentation cases in `PushWorkerTest` (drops, notices, retry-after-refusal, Nextcloud's own 404 kept) and `TrackChangesTest` (archive and rename answered 423). Pushing with `set` / `increment`: JVM `TickRepositoryMathTest` (`counterTap`), plus cases in `ServerFeaturesTest`, `PushFailureTest` (422) and `TickDtoTest` (`TickYesNoResponse`); instrumentation `MigrationTest.migrate3To4_…`, the `set` / `increment` cases in `PushWorkerTest` (an answer cut off mid-body and a 502 both resend the same key and delta; the key is in Room before the request leaves; a tap during a request is kept, `tapDuringPush_isKept` / `untickDuringYesNoSet_isKept`), `TickRepositoryTest` (rows marked for removal, never deleted; pending changes) and `SyncManagerPullTest.queuedUntick_…`. With the rig's three new flags left false, every older `PushWorkerTest` case covers the fallback unchanged. The rig's `seedServerFeatures()` stores its flags without a pull. **Lost answers use `SocketPolicy.DISCONNECT_DURING_RESPONSE_BODY`**, not a disconnect before the headers: OkHttp may silently retry a request whose connection drops before them, and the retry takes the next queued response. Added after the original Phase 5 pass: `AuthProberTlsTest` (untrusted-chain handshake → `UntrustedCertificate`, needs the `okhttp-tls` test dependency for MockWebServer over HTTPS), `SyncCancellationTest` (a cancelled caller can't tear down a Room transaction), `SyncCoordinatorTest.signOut_thenSignInAgain_leavesDatabaseUsable`, and three `BasicAuthInterceptorTest` subpath cases. Number and Choice: JVM `NumberValueTest`, `ValueCellTextTest`, `ValueLabelsTest`, `NumberFieldTest`, `NewTrackFormTest`, plus cases in `TrackTypeTest`, `TickDtoTest`, `TrackDtoTest`, `NoteStatsDtoTest`, `ServerFeaturesTest`, `TodayTextTest` (`valueLevel`, `squareLevel`), `WidgetModelsTest`, `TrackDetailViewModelTest`, `TracksHelpSheetTest`; instrumentation `MigrationTest.migrate5To6_…` and cases in `SyncManagerPullTest` (values, options, `awaitingSync`, stats range), `PushWorkerTest` (`number_…`, `choice_…`), `TickRepositoryTest` (`setValue_…`), `TickCellInteractionTest`, `TrackSettingsUiTest` (New track). Not yet covered: `ValueEntryActivity`, the Number card / Choice sheet and Today's control in Compose tests, and the widget node tests for the new cells. Today and notes: JVM `NoteTextTest` (`cleanNoteInput`, `normaliseNote`, every `planNotePush` case), `TodayTextTest` (`dayKind`, `runText`, `levelFor`, `squareWindow`), `HelpSheetTest`, `TodayViewModelTest`, `NoteStatsDtoTest`, plus cases in `ServerFeaturesTest` and `PushFailureTest` (409); instrumentation `NoteDaoTest`, `NoteRepositoryTest`, `DayTitleTest` (ICU titles; the UK full date with the year is "Wednesday, 21 October 2026" — the comma is ICU's), `TodayUiTest` (row, spacing, wrapped streak, locked-day taps, card guards, bar), `TodayOpenDayTest` (a day sent by navigation wins over the pager's restored page), `MigrationTest.migrate4To5_…`, and cases in `SyncManagerPullTest` (notes and stats in the pull, broken stats), `PushWorkerTest` (`note_…`: set, delete, append, settle, too long, no `notesAppend`, edits during set and append, 423 shared with ticks, 404 with/without reason, 409, ticks before notes, no flag), `SyncCoordinatorTest` and `TickCellInteractionTest` (the dot). The rig serves `notes`, `notesAppend`, `stats` (default false) and has a settable `today` clock. What is still **not** covered: the `<certificates src="user"/>` trust anchor (no test can populate the device user CA store — verify manually on an emulator with a CA installed) and anything at `NavHost` level, which is where both navigation regressions came from. Run via `./gradlew :app:testDebugUnitTest` and `./gradlew :app:connectedDebugAndroidTest`. **The instrumentation suite needs an emulator with ≥ 4 GB RAM** (`hw.ramSize` in `~/.android/avd/<name>.avd/config.ini`; cold-boot after changing it). A 2 GB Google-APIs AVD gets the test process OOM-killed before any test runs — the symptom is a misleading `Starting 0 tests … Process crashed` with `lowmemorykiller: Kill 'com.martinhammer.tickdroid'` in logcat, not a real test failure.

**Testability seams introduced in Phase 5:**
- `data/time/Clock` — interface + `SystemClock` impl, bound by `di/TimeModule`. Injected into `JournalViewModel` and `PushWorker` so tests can pin "today". `TrackEntity` / `TickEntity` still default `updatedAtLocal = System.currentTimeMillis()`; if a future test needs deterministic timestamps, repos can pass `clock.nowMillis()` explicitly.
- `Credentials.basicAuthHeader` switched from `android.util.Base64` to `java.util.Base64` (byte-equivalent, JVM-testable).
- `SyncScheduler` made `open`, with `WorkManager.getInstance` deferred to a `lazy` so test subclasses can be constructed without WorkManager initialized.
- `SyncCoordinator.stop()` (`internal`) cancels the observer scope so tests can tear down without dangling wipe calls on a closed DB.
- `SyncIssue` + `computeSyncIssue` + `toLabel` extracted from `JournalScreen.kt` to `ui/journal/SyncIssue.kt` for JVM testability.
- `TickCell` composable made `internal` so the Compose test can render it directly.

The shared instrumentation rig is `app/src/androidTest/.../sync/SyncTestRig.kt` — wires in-memory Room + MockWebServer + Retrofit/OkHttp + a real `AuthRepository` pre-seeded as signed-in, plus a real `ServerFeatures`. **The rig answers `GET /ocs/v2.php/cloud/capabilities` itself** (from `rig.archivedTracks`, or `rig.capabilitiesOverride`), because every pull starts with it and would otherwise eat the next queued response. So: enqueue through `rig.enqueue*` (MockWebServer's own `enqueue` casts the dispatcher to `QueueDispatcher`, which is final, so the rig wraps one), and read requests with `rig.takeApiRequest()`, which skips capabilities calls. Reused by `SyncManagerPullTest`, `PushWorkerTest`, `SyncMutexTest`. The rig's `json` is public for `PushWorkerTest.buildWorker`, which also passes a recording `PushNotices` subclass (`notices.shown`) so refusal messages are asserted without toasts. JSON fixtures live under `app/src/androidTest/assets/ocs/`.
