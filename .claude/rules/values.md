# Number and Choice in the UI

- **Cells** (`TickCell`, both Journal layouts; `WidgetTickCell`): a Number shows `numberCellText` (`ui/journal/ValueCellText.kt`, pure, `ValueCellTextTest`): the value at the track's places without grouping at 16/13/11/9sp, then rounded to a whole number at the same sizes, then `CompactDecimalFormat`'s short form. "Fits" is an **estimate** (tabular digits ~0.58em, separators 0.3em, 3dp padding a side) so the Journal and the widgets (which can't measure) always agree; widgets pass a slightly wider digit advance. A Choice shows `choiceShortLabel` or, with "Journal cells" = Place number (or a place with no option), the place in a circle at 72% of the cell. Empty editable cells: faint "…" (Number) / ▾ (Choice) at 35%. TalkBack: `valueDescription` (T24, "Run, 10.4 km"). A tap on an editable day calls `onOpenEntry` (no long-press).
- **Entry layer** (`ui/entry/ValueEntry.kt`, `ValueEntryLayer`): the **Number card** (built like the note card, `CloseWithKeyboard` is now shared in `ui/common`; Done saves or, for text it can't save, toasts and stays open; a tap outside / Back / closing the keyboard saves and closes, or closes with T21 / L15 / T22; `ON_STOP` saves a valid change; the field opens **without grouping**; `numberFieldChange` filters input and ungroups pastes; the decimal pad, with `TYPE_NUMBER_FLAG_SIGNED` added via `InterceptPlatformTextInput` only where negatives are allowed — check Gboard and Samsung Keyboard by hand) and the **Choice sheet** (`ModalBottomSheet`, one `selectable` row per option, Clear once the day has a value; dismissing changes nothing). Nothing is written when the value equals what's shown after rounding. The Journal and Today keep the open entry (`EntryTarget`) in their `SavedStateHandle` (`JournalViewModel` now takes one); Today never has the note card and the entry open together, and its pager doesn't swipe while either is.
- **Today**: Number and Choice rows draw `ValueControl` (112 × 48dp) in place of the cell, at the row's end; a Number with grouping and unit (`todayNumberFit`: the unit goes first, then the value shrinks; never cut), a Choice's full label + ▾; "… km" / "… ▾" when empty. Squares use `squareLevel`: a Number by `valueLevel` on the stats range (`minValue`/`maxValue`), an ordered scale on 1..n, a plain list at level 2.
- **Widget window** (`widget/ValueEntryActivity.kt`): a Number or Choice cell's tap is `actionStartActivity(valueEntryIntent(…))` **directly** (an `ActionCallback` starting it would be a trampoline, blocked on Android 12+), with a **unique data URI per cell** (`valueEntryUri`), or every cell would share one PendingIntent. Translucent theme (`Theme.Tickdroid.Translucent`), `taskAffinity=""`, `excludeFromRecents`, `adjustResize`, not exported. Refused before showing as `WidgetTickHandler` refuses taps (signed out, gone/private/archived → closes; earlier day → "New day: tap again to tick" + `onDayChanged`; awaiting sync → T20). The save runs `NonCancellable` on `lifecycleScope`, then every widget redraws and the window finishes without animation. Its ViewModel and state are public (Hilt).
- **New track**: four segments behind the flags (labels through the shared `SegmentLabel`); a Number's Unit / Decimal places (`ExposedDropdownMenuBox`) / Allow negative; a Choice's options in a `ReorderableColumn` (drag, "Move up"/"Move down" actions, ✕ above two, Add option up to 99, Next on the last adds one) with the one inline error in the app (T23 under a duplicate, via `supportingText`; `canAddTrack` / `duplicateOptionIndexes`, `NewTrackFormTest`). Both types' fields are kept while switching; only the chosen type's are sent (`NewTrackSettings`).
- **Track screen**: `TypeSettingsSection` (`ui/settings/TrackTypeSettings.kt`) under Private: Unit (the whole row → `ChangeUnitDialog`, empty allowed; the pencil is a plain icon so it ends at the edge like the ▾), Decimal places (menu), Allow negative; Options (tap → `RenameOptionDialog`), Ordered scale, and "Journal cells" (segmented, **not** behind `OfflineGuard`). Each server setting shows pending like Private (`TypeSettingsState`); left out while `awaitingSync`.
